# Resume checkpoints

Use `LVR resume status` once the journal and state agree. The summary includes dates and paths to inspect. It does not launch research, agents or installers. On resume, check the Section Record, saved files and journal together before continuing any operation. If Node is unavailable, inspect those same files and wait for the helper to rebuild state or check pointer drift.

1. **Freshness.** `research.expired` comes from `LVR cite check --all` and the limits in `freshness.json`. `framework.expired` covers stack and library deadlines. Before continuing an interview, compile, or resumed task that relies on the evidence, recheck expired facts from current sources. Use Step 4b for a real search and fetch. For expired selected versions, run live `signals --refresh` for the recorded candidates and exact pins, verify official docs and rerun `framework rank`. Log fresh observations and keep old decisions unless the owner accepts a different choice. If refreshing a closed file would change the approved plan, send the user to `/lvr-review-plan` with the affected fact and source. If tools fail, preserve the checkpoint and stop. A tool outage cannot supply an unverified research marker.
2. **Context research.** For a missing or unfinished brief, use [the Domain Brief procedure](sections/S0-domain-brief.md). Resume at the first required heading with neither recorded findings nor a documented empty result. A journaled RQ entry with an unfinished disk section calls for completing its matching rows from evidence. For a Section scan, a finished RQ entry is reused. Check the recorded `Became` links and show only open findings. A missing entry calls for the Section scan. A failed search uses its real attempt and note. A web tool outage goes through Step 4b.
3. **S5b.** Read the [framework procedure](sections/S5b-framework.md). With a current signal snapshot and no choice, inspect the exact pins, eligibility and source freshness, then rank or resume the recorded comparison. Missing, invalid, expired or incomplete data calls for collecting only the missing usable evidence. With a journaled current choice, retain it and close the remaining record or Section step. Keep completed stack choices and library slots separate. Confirm a replacement only when needed.
4. **Delegation.** For each open AG entry, check its Section Record, cited result and the actual harness. If the task is still running, keep its checkpoint. If a complete result exists, validate it, merge it and journal completion under the same ID. Otherwise retry the original bounded read-only task under its existing ID and capture the result once. If the original transport is unavailable, close that attempt as failed and start one inline fallback with a link to the original ID. Use installed `agents.json` and routing when available. Scope, user access and write limits still apply. Closed entries are done.
5. **Boosters.** Inspect `interrupted_paths`, the journal and the harness skill list. A staged install with verified pin and no deployed copy resumes from native staging or `booster deploy`, whichever is missing. An owned, recorded copy that is loadable is reused. For an existing untracked path, check it as user-owned and preserve it. Keep interrupted removal folders until the exact receipt and journal have been reconciled. Use `LVR booster plan --section S --harness NAME` and the [project-local lifecycle](booster-lifecycle.md) for missing applicable skills. Pending conditions wait for a decision. Reference-only tools are read at the cited pin.

For a legacy project entering S1 or later without a confirmed profile, use `references/profiles/` and the owner's recorded choices, then confirm the type before applying profile additions. To find the interview procedure, use the installed `lvr-init-new-idea` Section and its product profile, booster registry and optional `agents.json`. Use the shipped guides and conventions when the init skill is unavailable, and record that limitation.
